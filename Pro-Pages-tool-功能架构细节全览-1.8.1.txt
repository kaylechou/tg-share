一、概述
------------------------------------------------
1.1 是什么
  Pro Pages tool（桌面版曾用名“转歌词”，productName 仍为“转歌词”）是一款歌词
  分页工具：把歌词文本、歌谱图片、PDF 歌谱、字幕文件整理成 ProPresenter 可直接
  导入的分页歌词。只要歌词，不要音符，不做谱面、不做记谱。

1.2 给谁用
  教会敬拜场景：把诗歌歌词做成 ProPresenter 用的分页幻灯片，现场放歌词用。
  教会电脑上的 ProPresenter 为 21 版。工具保持公开、不收费、不商业化，仅在
  单一教会内部使用。

1.3 只做歌词，不做谱面
  歌谱图片、PDF 只识别其中的歌词文字，不认音符、不认和弦（和弦行、简谱数字行、
  谱头信息在整理时去掉）。背景不在工具里做，背景在 ProPresenter 里另配。

1.4 两种形态
  - 桌面版：Windows / Mac，Electron 应用，离线可用（除翻译、云端识别、搜索需联网）。
  - 网页版：Cloudflare Pages，浏览器打开即用，另有 PWA 安装。

三、功能总览（9 个平级模块）
------------------------------------------------
  顶部九个胶囊切换模块（按流程顺序）：
  导入歌词 / 校对歌词 / 拆页 / 字体 / 段落 / 样式 / 翻译·拼音 / 分页预览 / 歌库。
  搜索是“导入”里的页签，导出在“分页预览”里，设置与反馈在菜单与帮助里，
  不是独立胶囊。流程主线：导入 → 清理 → 拆页 → 字体 → 段落 → 样式 →
  翻译 / 拼音 → 分页预览 → 歌库 → 导出。

3.1 模块一：导入歌词
  能做什么：
  - 粘贴歌词文本载入（一行一句，段落间空一行，段落名单独一行），点
    “载入并拆页”；打开 .txt 文件，歌名自动取文件名。
  - 歌谱图片、PDF 识别：只取歌词，不认音符。识别引擎三选：
    （1）快速识别（默认）：本机即开即用，33 门识别语言数据已内置；
    （2）增强识别 · PaddleOCR：本机识别、图片不上传，中文小字更准，
    桌面版模型已内置，网页版首次需联网下载模型，失败自动回退快速识别；
    （3）云端识别：大模型识谱，谱面复杂、本地认不准时用。
  - 字幕文件 .srt / .lrc / .vtt / .ass 直接导入，自动去时间轴和序号。
  - 全网搜索页签（第 1 步第三页签）：填歌名（可再填歌手、专辑）搜歌词，
    候选点“查看并编辑”先看全文、结果框可直接改文字，点“生成分页预览”
    即用改后歌词拆页；有“换一换”、重新搜索、相关性门槛、各路结果明细、
    简繁双搜繁转简、歌名英日韩轮询。搜不到不编造；空歌词候选直接跳过。
  识别语言：歌谱识别语言 33 项（默认多语言混合）；识别前预处理（放大、
  灰度、对比增强、整块文本模式保行序）。
  云端识别提供方与模型（密钥按提供方分别保存、只存本机，先测再存）：
  Gemini（默认 gemini-3.5-flash-lite，另有 3.8-flash、3.6-flash、
  2.5-flash、2.5-flash-lite、2.5-pro）、智谱（glm-4.6v-flash、glm-4v-flash）、
  通义（qwen3-vl-plus、qwen-vl-plus）、硅基流动（THUDM/GLM-4.1V-9B-Thinking）、
  另有 OpenAI、Claude、DeepSeek、Kimi、豆包的模型位。识别优先直连各家接口
  （桌面走主进程，网页直接调接口），只有发不出去才自动切换，提供方拒答
  （如 401）即最终结论、不切换；失败自动回退本地识别。识别出的歌名、歌手
  自动填入歌名／歌手框（已有内容不覆盖）。
  搜索三级路由：直连 → 备用线路补位 → 免费代理兜底；抓取按响应头与 meta
  判定编码解 GBK/Big5，实体单遍全量解码，损坏内容自动降级重抓。桌面版直连
  走主进程本机网络（不受浏览器跨域限制），本机能直达的站不再绕备用线路。
  搜索全量出结果：三路全跑完再合并，不再找到就停；直连加百度、Bing，四路并行。
  歌词来源口径：先穷尽技术手段，实在没有才弹登录。流媒体与歌词提供商专用
  抓取：KKBOX、TIDAL、Spotify、Qobuz、Musixmatch、Genius；两档来源都做，
  第一档直接抓取，第二档需登录授权（应用内弹窗共享会话，桌面版可用）。
  Musixmatch 是唯一例外：只走公开页抓取，无密钥、无登录；公开页抓不到，
  点状态区下方的“跳过这一步”，直接进网页搜索，迟到的结果不再追加。
  授权先测再存：其它网站按该站实际反馈决定授权方式，填密钥或登录后先测可用、
  可用才保存；登录过的站记在本机（localStorage 键 lyricAuth），下次不再重复问。
  第二档登录可跳过（只桌面版）：CCLI SongSelect、Melon、Bugs、Genie、Uta-Net、
  YouTube Music 登录弹窗加“跳过这一步”，点后关弹窗、该候选标记已跳过、
  登录按钮隐藏。
  拦截页跳过可自选：候选正文抓取弹拦截页提示时，取消改为跳过本候选；跳过后
  回候选列表、还是自动取下一个，由用户在设置里自选其一，默认回候选列表；
  设置存本机、刷新不丢。
  共识高亮：全部结果出齐后，工具比对各来源文本，高亮推荐复制文本（只作推荐，
  不静默覆盖原文）。
  搜索可手动停止、暂停、继续（1.8.1 新增）：搜索进行中，状态区下方有停止、
  暂停按钮；点停止彻底终止；点暂停停住，再点继续从断点恢复，不重搜。
  局限（已如实记录）：非瞬时取消在途请求（2–5 秒，最长约 20 秒）；暂停粒度
  为阶段边界；只覆盖主搜索，“换一换”未接。
  搜索受限提示（1.8.1 新增）：候选少于 3 条且确实有引擎受限时才显示，写明
  哪个引擎受限、可开网络工具重试或改用百度；正常有结果时不提示。
  共享歌库：全网搜索亦搜共享歌库，共享结果优先排；首次共享先弹同意说明，
  同意后才共享，同意可随时撤回。

3.2 模块二：校对歌词
  能做什么：
  - 对照原谱改错字，空行分段，段落名单独一行；导出以第 2 步校对后的歌词为准。
  - “谱面过滤＋分组”：一键去掉和弦行、简谱数字行与谱头信息，按主歌 / 副歌 /
    桥段等段落分组；“谱头清除”：第一句真歌词前整段去掉，专辑 / 原曲 / 年份 /
    拉丁乱码行在正文任何位置也删；谱头粘连行（如速度数字与标题粘连）过滤。
  - “智能整理结构”：自动去掉时间轴、序号与句间空行；重复段标副歌，其余依次
    标主歌；晚出现的独立段标桥段，结尾短段标尾声；段落名可再改。
  - “智能清理”：只去汉字间空格，英文、韩文词间空格原样保留；“去除标点”
    默认开；断句规则是先按标点断句再去标点，碎行合并看标点。
  - “去括号拼音”：第 2 步默认开启的开关，只有括号内全部为合法拼音音节才
    连括号去掉，英文与说明括号保留。
  - 繁简互转：校对区转简体、转繁体一键全文原地互转，只转歌词正文，歌名／歌手
    框不动，空行分段与段落名行位置不变；歌词菜单同步有转简体、转繁体两项；
    简繁转换先用短语表（如“裸干”不单字转“幹”），短语表按需加载，加载失败
    退回原有转换。
  - 副歌合并：两遍词不同的副歌按演唱顺序排进同一副歌段；双行歌词：谱面上下
    两行歌词的，开“双行歌词”再整理，会按两遍拆成主歌一、主歌二。
  - 红清单：含汉字又删过拉丁乱码的行，整理后下方红色清单列出原行、删掉的
    乱码、删完的样子。
  - 纯粘贴分段标注与可疑行标记：粘贴的歌词也能分段标注，可疑行单独标记。
  - 段落标记多语言识别：日韩＋世界常规语言段落词都能认，段落名按标记语言输出
    （[Chorus]→Chorus、[サビ]→サビ、[후렴]→후렴，无标记推断用歌中已出现标记的
    语言，全首无标记按歌词主导语言）。
  - 清空范围自己选：清空时自己选范围，保留“全部恢复默认”；换新歌词、换新歌名
    时自动清掉之前设置；“沿用上一首设置”默认不续用；自己改的设置可存为
    自定义预设，名字可编辑；换新时有独立追加按钮，追加不重置。
  - 搜索歌名 / 歌手同步到校对：网页搜索后，校对步骤的歌名 / 歌手自动同步
    （只写非空，不清空）。状态不确定：1.8.0 文档列为新增，更新清单写
    “已做未部署”，是否随网页 1.8 上线未逐一核实（见附录 A3）。
  - 语义纠错建议：本地词典＋搭配检查，只标建议、不自动改，接受才改行并同步导出。
  已知问题（未修，见第十节）：markerClass 用子串匹配判段落名，会把“副歌预热 /
  副歌倾听”误判成副歌段；修法已给出，未批。

3.3 模块三：拆页
  - 按段落、行数或字数拆页（字数 6–80 可调，默认 24 字，整行装页不拆行）；
    分段方式：按段落拆页或连续拆页。
  - 段落名作标签或正文；段落名作分组，标签颜色一并写入导出。
  - 空白页不进导出：空白页只在预览里可见，txt / .pro / .pro6 / .pptx 都不含。
  - 单行过长逐页提示；在当前分页下面逐页提示单行过长。
  - 歌名页开关默认开，新歌自动建歌名页（只写歌名与歌手，译文与拼音不编造，
    没有就不写）；关掉开关可不贴歌名页；开关选择跨刷新保留。
  - 同页下一句：歌词页可开同页下一句，显示页内最后一条的下一句；段末下一句
    可自定义；仅歌词页可用，开关默认关；无下一句时不产生多余元素。
    下一句设置：只显示原文，与当前歌词增比例或直接设磅数。
    已知问题（staging 未发版）：下一句拖到右边会变竖排，根因已定位并修过，
    待用户验证。

3.4 模块四：字体
  - 字体（微软雅黑 / 黑体 / 宋体 / 楷体 / Arial 为 5 个内置选项，另可枚举
    本机已装字体）、字号直接输入具体磅值（全页统一，与百分比滑杆同步，
    60pt = 100%）、粗细、对齐、文字颜色。
  - 字体启动枚举＋缓存：启动先显示缓存字体，再后台强制刷新，新装字体能进来；
    进入字体模块时预加载字体列表，首次打开下拉不再只显示 5 个内置字体。
  - 字体颜色渐变：只支持两色，做 .pro / .proTheme / .pptx ＋预览；.pro6 不做；
    角度＋色标列表，元素级＋逐段级两处；.proTheme 样例 298.0°；教会电脑实机验。
  - 字体缺失预警：导出时提示缺失字体（输出一致性 7 项之一）。
  - 字体规则：选字体只从 Windows / WPS 自带字体清单挑；隶书随 Office 安装，
    不在 Windows 系统清单里；用户手机 WPS 实测没有微软雅黑。

3.5 模块五：段落
  - 段落预设：行高倍数、行距百分比、段落间距、字符间距、边距（左 / 上 / 右 / 下）、
    描边（开关 / 宽度 / 颜色）、阴影（开关 / 角度 / 偏移 / 模糊 / 透明度 / 颜色）。
  - 每个段落标签的颜色逐个改（默认主歌蓝、副歌粉红）。
  - 改动同步进预览与 .pro / .pro6。

3.6 模块六：样式（主题样式）
  - 主题样式 34 个（来源说法不一，见本节末尾）：1.7.0 时为现有 24 个＋新通用
    主题 10 个；34 个主题按歌词分页、歌名页、原文、原文＋多语翻译、
    原文＋多语翻译＋拼音编组，可多组；名后备注用途，备注随语言翻译；主题名与
    组名随工具语言五语翻译；只用通用名，不带背景，不内嵌字体。
  - 新通用主题 10 个：下方半透明条、线框全幅、侧边竖条、中央圆、中央菱形、
    上下双杠、半透明框、上方半透明条、歌名页线框、歌名页双线。
  - 形状：矩形、直线、竖条、圆、菱形、框；可设位置尺寸、旋转角、填充色与
    不透明度、描边宽与色、框边开关、圆角。文本框可设填充色、内边距、行分隔符、
    两端对齐、行距档。歌词 slide 可写 1–3 个文本框，原文、译文、拼音各绑一框。
  - 逐字、逐句、逐段样式：每段、每句、每字可设字体、字号、颜色、加粗；歌名页
    四行（歌名、歌手、译文、拼音）均可按逐字、逐句、逐段设样式，拼音按音节计。
  - 歌曲自带样式：歌曲记录存下歌名页逐字、逐句、逐段样式；从歌库载入时用这首歌
    自己的样式；库导出时同样用歌曲自带样式；老记录没有存样式时按原有方式回退。
  - 形状在 ProPresenter 内的显示效果待实机验证；主题形状自适应：框尺寸由文本
    实测推导，框宽按全歌最长单行定，多语取最长者，落 .proTheme；歌名页按歌名长
    自适应（只 .proTheme 自适应，UI 写明范围）。
  - 选主题时提示最多字数、行数；整体与每页设置时都提示。版式要点：字号观众可见、
    原文行距不挤、行间间距与字号比例合适、铺满屏幕。
  - 主题样式数量核对（未核实）：文档现写 34 个（24 现有＋10 新通用）；

四、导出格式细节
------------------------------------------------
  导出四选一：txt、.pro（ProPresenter 7）、.pro6（ProPresenter 6）、.pptx。
  另有 .proTheme 主题样式文件（各页分别下载，不要 zip）。菜单里另有导出
  .proBundle。空白页不进任何导出，只在预览里可见。
  根本定性（2026-11-10 实测结论）：.pptx、.pro、.proTheme 导出全是手写格式，
  是反复出格式问题的根子。

4.1 .txt（纯文本，不带样式）
  - 每页开头加段落名行，只写段落名本身、不加冒号（如“主歌一”“副歌”），
    按分组分段；无段落名页不加；空白页不进导出。
  - 段落之间以分隔符连接、最后一段不加；导出不再带页末空行；txt 结尾不带换行。
  - 导入 .txt 时，光秃段落名会被当成该页第一行歌词上屏；分组顺序只靠 PlayOrder；
    ProPresenter 内分组走 .pro 导出。（H7 定案，用户已接受，不再改格式。）
  - 多语译文和拼音行一并写入。

4.2 .pro（ProPresenter 7，最新版本格式）

  - 段落名作分组，标签颜色随分组写入；文本框铺满 1920×1080（边距为 0 时）；
    边距不为 0 时按边距内缩；每页写文字行与主题形状，页末不带空行。
  - 导出幻灯片为 1920×1080；歌词 slide 可写 1–3 个文本框，原文、译文、拼音各绑一框。
  - 形状：按 ProPresenter 21.4.2 真实安装包模板核对，51 项对齐
    （已做 staging，未发版，见第十节）；字号只缩小；
    Windows / Mac 目标平台选项。
  - 输出一致性 7 项（已做 staging，未发版，见第十节）：加 scale_behavior
    自动缩小、预览改实测字宽、单行过长逐页提示、
    统一三处内边距、预览画出形状、130 / 140 磅下一句底部裁切修复、字体缺失预警。
  - 7.16 兼容：用户导出 .pro 被拦 24 处，全是 Element 字段 4（rotation，未旋转写 360，

五、架构
------------------------------------------------
5.1 总览
  桌面版（Electron）＋网页版（Cloudflare Pages）同一套渲染与导出逻辑，
  桌面版多主进程能力（直连、更新、菜单、字体枚举）；歌词搜索中转 Worker、
  反馈后端 Worker、共享歌库中央 Worker 是三个独立的 Cloudflare Worker；
  更新检查与下载走 GitHub 直连＋备用线路。

5.2 桌面版（Electron）
  - 源码：files/desktop-lyric-tool/；package.json（name lyric-tool、
    productName 转歌词、version 1.8.1，main main.js）；main.js 2644 行；
    app/index.html 32202 行（渲染层，含全部 9 个模块与导出逻辑）；
    app/menu.js（193 行，菜单）、app/preload.js（443 行）、
    app/theme-manager.js（79 行，5 个界面主题）、app/theme-*.css（5 个界面主题），

    app/semantic-check.js（语义纠错）、app/vendor（Tesseract.js、pdf.js、
    PaddleOCR、OpenCC 等）。
  - 主进程：本地页面通过 app:// 自定义协议加载（standard + secure），
    Tesseract.js / pdf.js 的 worker、fetch 本地文件像 https 页面一样正常工作，
    不用真的联网，也不用关 webSecurity。
  - 四进程分工（帮助与关于里写明）：主进程、渲染进程、GPU 进程、工具进程；

    PaddleOCR 模型已内置本机）。
  - 流量全加密：所有对外请求一律 HTTPS；域名加密 ECH，不改系统 DNS、不覆盖
    代理设置。
  - 字体启动枚举＋缓存：启动先显示缓存字体，再后台强制刷新。

六、数据与同步
------------------------------------------------
6.1 歌库数据（本机 JSON）
  - 歌库数据存在本机，以 JSON 形式存取；歌曲记录含歌名、歌手、歌词正文、
    分类、主题样式（各页所用主题）、逐字／逐句／逐段样式（歌名页四行）。
  - 歌库 JSON 的字段级结构未在来源中逐项列出，本文不编造字段名。
  - 保存时记录该歌各页所用主题；从歌库载入时用这首歌自己的样式；库导出时
    同样用歌曲自带样式；老记录没有存样式时按原有方式回退。
  - 云共享的当前文档、样式模板、主题文件、设置，密钥与 PAT 不进载荷。

6.2 GitHub 手动同步（歌库）
  - 同步方式：手动同步（不是自动同步）。流程：手动建仓（公开／私有自选，
    默认私有）、索引搜索拉取、冲突保留双方、删除不同步、只同步歌库。
  - 同意只问一次：同步知情同意只首次弹一次，常驻显示、可撤回。
  - 去重规则：以歌词为主、歌名歌手为辅；歌词哈希比对。
  - 导出为文件时按分类层级建文件夹；文件夹导出先过版权确认。
  - 分享：选歌生成分享清单，先过版权确认，确认后才发出；分享可作废，
    作废后对方不再能用；分享可转发，转发时同样提示版权确认；接收方导入时
    先预览，确认后再进歌库。

6.3 隐私边界
  - 运行日志不记歌词正文与搜索词，只记操作、环节、错误码、耗时，留 1000 条。
  - 密钥（翻译 / 拼音 / 云端识别）只存本机，先测再存；授权记录只存本机
    （localStorage 键 lyricAuth）。
  - 同步与共享不同步的内容：不含账号、密码、密钥、网址、联系方式与他人隐私；
    云共享载荷不含账号密钥。
  - 反馈截图最多 3 张；反馈内容以测试标记区分。

七、网络与搜索
------------------------------------------------
7.1 总原则
  - 一切网络流量一律先走直连、直连不通再走中转；401 不进中转。
  - 桌面版直连走主进程本机网络（不受浏览器跨域限制）；网页版直连受跨域限制，
    备用线路仍是最可靠的路。
  - 流量全加密：所有对外请求一律 HTTPS；域名加密 ECH，不改系统 DNS、不覆盖
    代理设置。

7.2 搜索引擎现状（2026-11-09 中转 relay 头修复部署后实测）
  - 中转百度：可用，8 条稳定。
  - 中转 Bing：0 条。Bing 对 Cloudflare 机房 IP 是 IP 级拦，中转无解；只有
    桌面直连（住宅 IP）才能用 Bing。
  - 中转 Google：engine_blocked（引擎被拦）。
  - 直连 DDG / Google：无 Karing TUN 时失败；桌面直连（住宅 IP）可用。
  - 搜索三级路由：直连 → 备用线路补位 → 免费代理兜底；抓取按响应头与 meta
    判定编码解 GBK / Big5。
  - LRCLIB：三腿与网页搜索三级全跑完再合并。
  - Musixmatch：唯一例外，只走公开页抓取，无密钥、无登录；公开页抓不到就跳过。
  - 拦截页：遇拦截／同意／验证／登录页直接弹给用户处理，处理完再抓；拦截页
    登录成功后 host 记进本机（localStorage 键 lyricAuth）。
  - 搜索与抓取口径：能直接抓就直接抓；授权后先测再存；能搜到就搜到吧，不再
    强求全通。

7.3 更新检查与下载
  - 更新检查：直连 GitHub API → 备用线路兜底，不动。
  - 更新下载双线路：点“立即下载”后自动选线路，不用每次问，顺序 GitHub →
    普鲁文（file.pluwen.com 第 9 分享，须先有对应版本文件才能走 B 线路）→
    中转兜底；后续版本用户自己手动上传，传完通知助手核对＋删旧版。
  - 8 连接分段下载、断点续传、SHA256 校验（对照表 SHA256SUMS.txt，不一致
    重下最多 3 次）；更新检查走直连 GitHub API → 备用线路兜底。
  - 普鲁文第 9 分享目前只有 1.5.0，1.8 / 1.8.1 待用户自己上传。

7.4 过审叫法（界面文案）
  - 中转 → 备用线路；VPN → 网络工具；代理设置、免费代理属标准叫法，保留。
  - 文档措辞保持短句，不出现外站／中转／限流字样。
  - 界面大陆受审查类词汇一律改过审的叫法。

八、界面与使用规则
------------------------------------------------
8.1 界面语言（五语）
  简体中文、繁體中文、English、日本語、한국어。顶栏“界面语言”下拉框切换；
  桌面版在语言菜单里切。主题名与组名随工具语言五语翻译。

8.2 界面主题（五种）
  活力粉青、科技冰蓝、经典暖纸、时尚紫罗兰、液态玻璃；默认经典暖纸。
  桌面版在视图菜单里切；网页版在顶栏“界面主题”下拉框里切。
  液态玻璃仅 chrome 样式层（顶栏、卡片、按钮等外壳样式）；选中胶囊与按钮
  颜色随各自主题配套。
  流程步骤颜色跟随 5 个界面主题（1.8.1 修）。

8.3 字体规则
  - 内置 5 种字体：微软雅黑、黑体、宋体、楷体、Arial；另可枚举本机已装字体
    （启动先显示缓存、再后台强制刷新）。
  - 选字体只从 Windows / WPS 自带字体清单挑；隶书随 Office 安装，不在
    Windows 系统清单里；用户手机 WPS 实测没有微软雅黑。
  - 字号直接输入具体磅值（全页统一，与百分比滑杆同步，60pt = 100%）。

8.4 版式要点
  - 字号观众可见、原文行距不挤、行间间距与字号比例合适、铺满屏幕。
  - 选主题时提示最多字数、行数；整体与每页设置时都提示。
  - 预览与导出尺寸自适应口径已定，不再写死 1920×1080；.pro6 钉死 1920×1080。
